## 🔬 Step 2：测试方法

> Agent 可用的工具：`proxy_send_request`（发包）、`browser_fill` + `browser_get_element`（浏览器测试）

### 2.1 基础探测

按顺序执行以下测试，每步记录响应差异：

1. **正常请求**：记录正常响应（状态码、响应体关键字段、响应时间）
2. **异常输入**：输入特殊字符，观察响应变化
3. **边界值**：超长输入、空值、特殊字符

### 2.2 分类测试方法

#### 场景 A：直接参数注入

```
操作步骤：
1. 在参数 X 后添加测试字符
2. 使用 proxy_send_request 逐字符测试
3. 对比正常与测试响应
```

| 测试输入 | 预期正常响应 | 可疑响应 |
|---------|-------------|---------|
| `'` | 200 + 正常数据 | 500 / 错误信息泄露 |
| `"` | 同上 | 同上 |
| `1` 替换为 `2-1` | 相同结果 | 结果不同 → 可能数字上下文 |

#### 场景 B：JSON/GraphQL 场景

## ✅ Step 3：确认漏洞

### 3.1 证据等级

| 等级 | 证据 | 说明 |
|------|------|------|
| 不充分 | 只有 500 错误、只有 WAF 拦截差异 | 不能确认 |
| 可疑 | 响应稳定出现差异、错误信息泄露查询片段 | 值得继续深入 |
| 基本确认 | 能稳定触发差异，并能确认是输入触发了特定处理逻辑 | 可标记 suspected_vuln |
| 明确确认 | 能证明输入被当作了代码/指令执行 | 漏洞确认 |

### 3.2 确认信号 checklist

- [ ] 输入单引号返回 500 但正常请求为 200
- [ ] 响应中包含输入回显
- [ ] 错误信息包含数据库/框架/模板引擎名称
- [ ] 响应时间出现明显延迟
- [ ] 响应内容随输入变化而变化

## 🔁 Step 4：失败恢复

### 4.1 常见失败原因

| 被拦截的特征 | 可能的绕过方向 |
|-------------|---------------|
| WAF 拦截单引号 | URL 编码、双写、Unicode 等价 |
| 参数没回显 | 看响应时间、看异步结果、看日志 |
| 返回始终相同 | 尝试不同 HTTP 方法、不同 Content-Type |

### 4.2 替代思路

当标准方法失败时：
1. 检查是否在**不同的请求层**（JSON → URL 编码 → Multipart）
2. 检查是否在**不同的请求位置**（参数 → Header → Cookie → 路径）
3. 检查是否在**不同的请求方式**（GET → POST → PUT → PATCH）
4. 检查是否在**不同的功能点**（同一个参数在不同接口行为不同）
