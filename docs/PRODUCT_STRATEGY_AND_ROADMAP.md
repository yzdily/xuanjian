3. **短期优化**：对齐你已有的三份方案——`CONFIG_UNIFICATION_REPORT`（已做）、`hollowing-optimization-plan`（空心化/保底/容灾）、`REDESIGN_AND_TESTING_PLAN`（domain/ports/DI + 全测试覆盖）、`XUANJIAN_AI_OPTIMIZATION_PROMPT`（提示词单源化）。短期只做**止血→根治→增强**，不重写业务。

### 1.3 我们的差异化护城河（代码已验证）

- **业务理解**：LLM 推导攻击假设（传统漏扫 ❌）。
- **假阳性铁律（核心资产）**：检测层硬规则（`core/fast_scanner.py` 410–748 行）+ LLM 审核员 `accepted/borderline/rejected` 双重过滤——即使 FAST 跳过危害验证也去误报。
- **报告可信度（新壁垒）**：本地已落地的 **空心化检测**（hollowing / `_detect_hollowing`）：识别"看似扫完实则 0% 真实完成"，杜绝虚假完成率——这是对企业客户极关键的可信信号。
- **浏览器 + 流量双驱动**：Playwright 交互、SPA 智能降级、CryptoHook 前端加密突破、mitmproxy 全量抓包。
- **方法论引擎 SKILL**：111+ 实战方法论 + Wooyun 历史库，用户可自定义——天然可做成**知识付费市场**。
- **合规报告**：`compliance_report.py` 内置模板，直连**等保 2.0 / 关基**需求（国内政企强诉求）。
- **多入口**：Web UI / Burp 插件 / REST API 已齐，天然支持 SaaS 化与第三方流水线。

### 1.4 SWOT

- **S**：双引擎去误报、报告可信、SKILL 生态、合规模板、MIT 可商用。
- **W**：上帝文件（7 个 >2000 行）、提示词散落 15 处、模式术语对外不一致、测试门禁仅 70% 且 e2e 缺失、与上游术语/版本漂移。
- **O**：国内等保/关基合规刚需、AI+安全的资本与采购热度、开源社区转化漏斗。
- **T**：上游分叉成直接竞品、双用途合规风险、LLM 成本压毛利、大厂（如安全厂商）下场做同类。

## 2. 长期盈利目标（商业模式）

### 2.1 核心约束（决定不能做什么）

- **MIT 开源**：任何人可免费自托管 → 不能靠"软件授权"赚钱，只能卖**托管/服务/差异化数据**。
- **双用途（dual-use）**：属安全测试工具，**必须授权证明 + KYC + 滥用防护**，否则触碰法律红线，也无法对企业销售。
- **LLM 成本是毛利杀手**：DEEP 模式重度调 LLM，token 费随扫描量线性上升 → 必须靠 FAST/本地规则 + 小模型 + 经验复用（Memory）把边际成本压下来。

### 2.2 推荐商业模式：Open-Core 漏斗

```
 免费社区 (MIT 自托管)         玄鉴 Cloud (托管 SaaS)          企业版 (私有化)
 ───────────────────         ──────────────────────         ───────────────────
 全功能自托管                 上传目标→托管扫描→报告          本地化部署 License
 社区 SKILL 库               按扫描额度/订阅计费              + 等保合规模块
 GitHub Star / 贡献          多租户隔离 + 用量观测            + SLA + 专属支持
        │ 转化 ↑                    │ 增值 ↑                      │ 大客 ↑
        └────────── 飞轮 ───────────┴────────── 数据/经验反哺 ────┘
```

- **社区层（获客）**：保持 MIT 自托管，靠 Star/口碑/安全会议获客，沉淀 SKILL 贡献。
- **Cloud 层（变现主力）**：用户不想管浏览器/代理/LLM Key/合规，买托管。LLM 成本由平台规模化采购（更低单价）+ FAST 保底规则摊薄。**这是毛利与规模化核心**。
- **企业层（高客单）**：政企/金融私有化，卖 License + 等保合规模块 + SLA，客单价最高、销售周期最长。

### 2.3 收入引擎与定价建议

| 产品 | 计价单位 | 建议定价（示意） | 目标客群 |
|------|----------|------------------|----------|
| 玄鉴 Cloud · 个人 | 扫描额度包（次/资产） | ¥99–299 / 月（含 N 次 DEEP 扫描） | 白帽/中小安服 |
| 玄鉴 Cloud · 团队 | 席位 + 资产数 | ¥999–4999 / 月 | 安服团队/乙方 |
| 企业私有化 | 年 License（按资产/节点） | ¥5w–50w / 年 | 政企/金融/关基 |
| 等保合规模块 | 增值包 | 企业版内含 / Cloud 加购 | 需过等保客户 |
| SKILL 市场 | 专家方法论分成 | 创作者 7 : 平台 3 | 红队/垂直行业 |

### 2.4 单位经济（关键变量）

- **边际成本 ≈ LLM token 费 + 算力（浏览器/代理）**。DEEP 全站扫描若耗 ~$1–3 token，定 ¥99–299/次的包仍有高毛利——前提是 **FAST 保底 + 经验复用 + 小模型** 把均摊成本压到 $0.2–0.8。
- **飞轮**：每次扫描的"经验沉淀（Memory）"让同类目标复测 token 下降 → 规模越大边际成本越低（数据护城河）。
- **风险点**：若用户全用 DEEP + 顶级模型，毛利会被 token 吃掉 → 用 `fast_minimal_checks` 保底 + 模型热切换（已支持 10 个 LLM）引导成本最优。

### 2.5 合规与风控（上商业化前的硬门槛）

- 强制**授权证明上传 + 企业 KYC** 才能发起 Cloud 扫描。
- 保留并强化 `DISCLAIMER.md` 法律底线；Cloud 侧加**审计日志 + 目标白名单 + 速率熔断**（WAF 感知调度已本地落地，可复用）。
- 禁止对未授权目标扫描；平台侧只接受"已授权资产"清单。

## 3. 短期目标优化过程（0–2 季度：止血→根治→增强）

> 对齐你已有的 4 份方案，避免重复造轮子。短期目标不是加功能，而是**把"能跑的原型"变成"可信、可测、可托管"**。

### 3.1 现状（代码事实）

- 7 个上帝文件（`fast_scanner.py` 4266 行、`crawler_core.py` 3704 行等）。
- 系统提示词散落 15 个文件，同一规则多份复制（漂移风险）。
- 测试 `cov-fail-under=70` 仅 CI 门禁，e2e/llm/slow 默认不跑；端到端行为缺保障。
- 模式术语对外不一致（代码 FAST/STANDARD/DEEP vs README Batch/Realtime/Packet）。
- 已完成：配置统一（14 常量）、镂空/空心化检测、FAST 保底、WAF 感知、补测三层兜底。

### 3.2 三阶段优化（直接复用已有方案）

| 阶段 | 目标 | 对应已有方案 | 关键动作 | 验收 |
|------|------|--------------|----------|------|
| **止血（P0）** | 报告可信、不崩 | `hollowing-optimization-plan`（OPT1–6 已实施，缺陷已修） | 固化空心化检测、FAST 保底、WAF 感知、补测兜底；**先合 P1 测试基座** | 报告完成率=真实完成率；0 严重误报回归 |
| **根治（P0–P1）** | 可维护、可测 | `REDESIGN_AND_TESTING_PLAN`（domain/ports/DI）、`XUANJIAN_AI_OPTIMIZATION_PROMPT`（Phase A/B/C） | 抽 `domain/` 纯函数、端口化 LLM/HTTP/Browser、提示词单源化（`_common.md`）、上帝文件拆分（<800 行）、模式术语统一 | 单文件 ≤800 行；安全铁律单源；`pytest` 全绿；diff cov ≥90% |
| **增强（P2）** | 可信 + 可观测 | 同上 Phase D/E | 假阳性回归语料库、快照/断言测试、结构化用量日志、README 与代码同步 | 新增误报样本必过 pin 测试；用量可归因到 caller |

### 3.3 短期 OKR（示例，0–2Q）

- **O1 报告可信度**：空心化检测 100% 触发；历史 4 类误报 + 每新增 1 类均有 pin 测试。
- **O2 工程可测性**：`domain/` 覆盖 ≥95%、全仓 ≥85%、diff cov ≥90%；CI 门禁强制。
- **O3 术语与体验一致**：代码与 README 统一为「深度×编排」两维度；Web/Burp/API 三入口术语一致。
- **O4 成本可控**：FAST 保底 + 小模型路由使 Cloud 边际 token 成本下降 ≥40%（为商业化作准备）。

## 4. 开发路线（Roadmap）

### 4.1 成熟度阶段

```
原型(现在) ──▶ 生产级可测 ──▶ 产品化多租户 ──▶ 商业化上线 ──▶ 生态飞轮
 能跑      可信/可测       Cloud-ready      Open-Core 三线    SKILL 市场+等保
```

### 4.2 阶段路线（时间盒为示意，按团队节奏调整）

| 阶段 | 时间盒 | 目标 | 关键交付 | 退出标准 |
|------|--------|------|----------|----------|
| **P0 基座** | 0–1Q | 止血 + 可测基座 | 测试基座/CI 门禁、空心化检测、提示词单源化、上帝文件拆分 | 报告真实完成率、单文件≤800、全测绿 |
| **P1 信任** | 1–2Q | 质量与信任飞轮 | 假阳性语料库、domain/ports/DI 重构、用量可观测、模式统一 | 覆盖率达标、误报率≤基线、术语一致 |
| **P2 产品化** | 2–3Q | Cloud-ready 架构 | 多租户隔离、计量计费、授权证明+KYC、审计日志、（可选）容器编排 | 单租户可托管、可计量、可审计 |
| **P3 商业化** | 3–4Q | 三线齐发 | 玄鉴 Cloud 公测、企业版 License+等保模块、定价/计费上线 | 首批付费客户、毛利为正 |
| **P4 生态** | 4Q+ | 飞轮与壁垒 | SKILL 市场、垂直行业方法论、CI/CD 集成、靶场基准榜 | 创作者生态、复购率↑、数据护城河 |

### 4.3 关键决策点（必须 early 拍板）

1. **Fork 策略**：合并回上游 / 长期分叉 / 只取不舍？→ 建议**长期分叉做商业版，同时持续向社区版反哺（保持 MIT 合规与 goodwill）**，避免与上游正面竞争消耗。
2. **开源 vs 商业边界**：哪些进社区（引擎/规则/SKILL）、哪些仅商业（Cloud 托管/合规/计量）？→ 用"托管与数据"而非"功能"做隔离，社区版保持完整可用。
3. **LLM 成本归属**：自管 Key（用户付）vs 平台代付（含在订阅）？→ Cloud 默认平台代付+模型路由优化，社区版用户自管 Key。

## 5. 风险与权衡

- **上游变竞品**：持续分叉需投入同步成本；用"托管/合规/数据"壁垒对冲。
- **双用途合规**：Cloud 必须 KYC+授权，否则不可商业化；合规是门槛也是护城河。
- **毛利被 LLM 吃**：靠 FAST 保底 + 经验复用 + 小模型路由；监控单扫描 token 成本。
- **重构不破安全**：所有优化须保证 `tests/` 全绿、假阳性规则行为一致、模式语义不变（铁律见 `XUANJIAN_AI_OPTIMIZATION_PROMPT` §2）。
