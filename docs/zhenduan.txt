诊断结果2根因（两层 + 一个我之前判断失误）
① 真正的病根：登录页那个"提交接口"从来没进测试队列

爬虫能识别登录表单，记成 CrawledForm.action（如 /login、/api/auth/login）
但匿名 fast 爬取不真提交表单（crawler_core.py:3465 检测到表单调 _fill_and_submit_form，匿名态下 submit_requests 为空）
FastScanner 的测试目标源 api_endpoints 只从真实抓到的网络请求构建（crawler_core.py:1549/1571）
结果：登录 POST 只被记为"发现一个表单"，从没变成绩可测 API → Phase 2 测不到它 → 整轮对登录页零产出
② 你看到的 ✅ 是误导

supplemental_test_agent.py:1030 的告警只在"一条流量都没抓到"时触发
登录页代理抓到了登录页 GET + 静态资源（total_scanned > 0），过滤后 0 新 API → 警告条件不成立 → 显示 ✅ 0 个，看着正常、实为空心
③ 我上一轮提的"爬取上限 30→100、超时 60→180"对登录页是错的

登录页就一页，翻来覆去爬 180 秒还是那一页——这就是你说的"爬那么费劲"。提高页数只对多页真实站点有用。
方案（建议顺序 A→B→C）
A. 表单接口桥接（治①，核心）
把"发现但未提交的表单 action（尤其登录）"注册为可测 API，让 FastScanner 在 Phase 2 直接测它（SQLi / 认证绕过）。

落地形态：独立纯函数 register_form_apis()（可注入 sitemap、可单测），在 chat_loop.py 处理 crawl_result 后调用，并在 Phase 0 报告列出"已补登的未提交表单接口"
效果：登录页也能被真测到，不再空心
B. 修正 ✅ 误导（治②）
supplemental_test_agent.py:1030 改为：代理抓到流量但过滤后 0 新 API 也打 ⚠️，提示"登录接口已由 Phase 2 覆盖 / 检查代理是否抓到登录 POST"。

C. 收敛爬取（治③）
回退 fast 爬取上限到适中值（crawl_max_pages≈50 / timeout≈120），或加"检测到登录页 surface 极小 → 提前收敛爬取轮数"。

附：那两个 task（task_1786087963_7fd60b / task_1786089188_f3e936）的"不对"本质是同一件事——fast 模式对单登录页站点抓不到可测接口，且日志用 ✅ 把空心扫描伪装成正常。A 修完才有实质产出，B 让问题可见，C 去掉无效等待。
